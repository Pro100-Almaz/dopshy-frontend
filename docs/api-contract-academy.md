# Контракт API академии

Что фронтенд уже умеет читать и писать. Ручки из первого раздела есть в
проде — на них работают экраны расписания, пробных и учеников. Ручек из второго
раздела ещё нет: экраны «Платежи» и «Контент бота» написаны под этот формат и
включатся без правок, как только бэкенд начнёт отвечать.

Источник требований — ТЗ `fs dopsy ТЗ финал.docx` и `box academy ТЗ финал .docx`
(разделы §2.3–2.7, §4).

Все ответы — в конверте `{ "ok": true, "data": { ... } }`. Авторизация: `Bearer`
токен менеджера либо заголовок `X-API-Key`. `{sport}` — `football` или `boxing`.

---

## 1. Реализовано (используется сейчас)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/{sport}/groups` | Расписание: по строке на каждый тренировочный день группы |
| GET | `/api/{sport}/trials?subscribed=` | Пробные заявки |
| GET | `/api/{sport}/students?subscribed=` | Ученики |
| PATCH | `/api/{sport}/trials/{trial_id}/attended` | Отметка посещения: `{ attended: boolean }` |
| PATCH | `/api/{sport}/trials/{trial_id}/subscribed` | Оформление абонемента: `{ subscribed: boolean }` |
| PATCH | `/api/{sport}/students/{student_id}/subscribed` | Смена статуса абонемента |
| PATCH | `/api/manager/academy_groups/{group_id}` | Правка группы: `group_name`, `max_cap`, `start_time`, `end_time` |
| GET | `/api/bot-status/contacts` | Статусы бота по контактам (передача диалога менеджеру) |
| POST | `/api/bot-status/{phone}/pause` · `/resume` | Менеджер забирает диалог и возвращает боту |

### Необязательные поля групп из ТЗ §4.1

Интерфейс уже показывает их, когда они приходят, и молчит, когда нет. Добавить
в `/api/{sport}/groups` их стоит: без них бот не может подобрать группу по
возрасту и смене, а менеджер не видит, какие группы бот вообще предлагает.

| Поле | Тип | Зачем |
| --- | --- | --- |
| `age_min`, `age_max` | integer \| null | Подбор группы по возрасту ребёнка (§2.2) |
| `shift` | string \| null | Смена: `Таңертең` / `Түстен кейін` / `Кез-келген` |
| `is_active` | boolean \| null | Неактивную группу бот не предлагает |

### Отдельная просьба: третье состояние посещаемости

`attended` — булево, поэтому «не пришёл» и «ещё не отмечено» на чтении
неразличимы, хотя по ТЗ §2.3 это два разных сообщения родителю. Сейчас
фронтенд помнит явную отметку «не пришёл» в браузере менеджера и опирается на
время занятия — это работает, но не переносится между устройствами.

Достаточно добавить в ответ `/api/{sport}/trials` одно поле:

```jsonc
"attendance_state": "pending" | "attended" | "missed"   // pending = менеджер ещё не смотрел
```

и принимать его же в PATCH. После этого локальный костыль можно убрать.

### Необязательные поля пробных из ТЗ §4.2

| Поле | Тип | Зачем |
| --- | --- | --- |
| `created_at` | datetime | Когда пришла заявка — сейчас порядок строится только по дню занятия |
| `shift` | string | Смена ребёнка (интерфейс уже показывает) |
| `school_time` | string | Время школы, чтобы видеть, почему бот предложил именно этот слот |

## 2. Ожидается: платежи и чеки (ТЗ §2.5–2.7, лист «Төлемдер» §4.3)

Экран `/{sport}/payments` готов. Пока ручки отвечают 404, он честно показывает
состояние ожидания и этот же список путей.

### `GET /api/{sport}/payments`

```jsonc
{
  "ok": true,
  "data": {
    "payments": [
      {
        "payment_id": 501,
        "child_name": "Диас Сапаров",
        "parent_phone": "77083334455",
        "discount": "Жоқ",                     // «Бар» / «Жоқ» / true / false — читаем любой вид
        "amount": 25000,                        // null, если AI не прочитал сумму
        "sender_bank": "Kaspi Bank",            // из чека
        "receiver_bank": "Halyk Bank",          // из чека
        "check_number": "#KSP-2026-114532",     // из чека
        "payment_date": "2026-08-05T10:32:00",  // из чека
        "due_date": "2026-09-05",               // до какого числа ждём следующий платёж (§2.6)
        "created_at": "2026-08-05T10:45:00",    // когда бот записал платёж
        "check_status": "Оқылды",               // Оқылды / Бұлдыр / Тексеру керек / Қолмен тексеру
        "is_active": true,                      // активный абонемент — по нему идут напоминания
        "confirmed": null,                      // null = менеджер ещё не смотрел
        "notes": "",
        "check_url": null                       // ссылка на файл чека, если он хранится
      }
    ]
  }
}
```

`check_status` принимается и по-казахски, и латиницей: `read`, `blurry`,
`amount_mismatch`, `manual`.

### `PATCH /api/{sport}/payments/{payment_id}/confirmed`

```jsonc
{ "confirmed": true }   // ручное подтверждение платежа менеджером (§2.7)
```

### `PATCH /api/{sport}/payments/{payment_id}`

```jsonc
{ "due_date": "2026-09-05", "is_active": true, "notes": "..." }
```

Нужно для §2.6: бот напоминает об оплате по `due_date` и только активным
абонементам, повторно — через три дня.

## 3. Ожидается: контент бота (ТЗ §2.4, §9)

Экран `/{sport}/bot-content` собирает то, без чего по ТЗ §9 бот не запускается.
Пока ручек нет, черновик лежит в браузере менеджера, а готовый JSON отдаётся
разработчику кнопкой. Формат JSON совпадает с телом `PUT`.

### `GET /api/{sport}/bot-content` · `PUT /api/{sport}/bot-content`

```jsonc
{
  "prices": {
    "trial": "бесплатно",
    "full": "25 000 ₸ в месяц",
    "discounted": "20 000 ₸ в месяц"
  },
  "kaspiLink": "https://pay.kaspi.kz/...",   // статическая ссылка, API Kaspi нет (§6.1)
  "adminPhone": "+7 700 000 00 00",          // фолбэк L3 (§2.8)
  "whatsappNumber": "+7 700 000 00 00",      // номер академии (§9 п.6)
  "paymentDay": "5",                         // число месяца для напоминания (§9 п.9)
  "faq": [
    { "id": "trial-price", "topic": "Цена пробного занятия", "kz": "…", "ru": "…", "required": true }
  ]
}
```

Темы FAQ фронтенд подставляет сам по ТЗ §2.4 (у бокса добавлены вопросы о
безопасности и уровнях групп); менеджер может добавить свои. Если бэкенд
пришлёт неполный набор, недостающие темы добираются из шаблона.
